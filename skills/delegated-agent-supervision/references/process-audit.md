# Auditing agent workflows without growing overhead

- Recover the referenced review and open cards first. Separate new findings from existing corrective work; do not create a second implementation of the same fix.
- Before expensive CLI audit fan-out, perform one bounded capability probe using the intended executor and sandbox. If local reads are structurally denied by policy, stop that branch rather than spending tokens on repeated equivalent shell attempts. Do not bypass the restriction or relax permissions; use an independently authorized read path and provide a sanitized evidence bundle if needed. An exit code 0 can mean the agent successfully wrote a failure report, not that the audit succeeded. Late completion notifications are not new findings when the failure was already handled.
- Rank by observed user intervention, active project work and risk. Session titles are weak overlapping signals, not usage shares. `parent_session_id` can represent continuations; filtering it to NULL can erase real project activity. Missing cwd is an attribution gap, not proof that context was absent.
- Snapshot inventories to JSON and deduplicate worktrees by `git rev-parse --path-format=absolute --git-common-dir`. Inspect manifests, entrypoint context, CI and delivery contracts for every inventoried project; label deeper reviews separately.
- Distinguish dollars, subscription quota, model calls, cached input and time per verified delivery. A money-only guard cannot enforce a subscription allowance. Validate outcome enums, run/session identity and real executor before drawing model-quality conclusions.
- Reuse native Projects, Kanban dependencies/completion contracts, monitor_script/no_agent, updater receipts and checkpoints before inventing another router or daemon.
- Verify local source, deployed runtime and synchronized bootstrap copies independently. Git sync of a stale copy does not distribute the runtime fix. Compare bytes/versions and exercise a fresh isolated installation before claiming cross-device readiness.
- For script-loaded exporters, verify the entrypoint contract: `runpy.run_path(..., run_name="custom_alias")` does not execute an `if __name__ == "__main__"` block. A silent cron completion can therefore be a no-op. Snapshot timestamps may intentionally change only with content; distinguish content revision from last successful observation, and enumerate current board stores/statuses instead of trusting a legacy single-DB filter.
- Audit Stop-hook reviews against the task boundary, not merely a silence debounce. Capture the applicable request and amendments, baseline/diff identity and per-run evidence; a first-ever session prompt plus the current mutable working tree can review the wrong scope. Group repeated reviews by source session/task and fingerprint before calling them duplicates. Empty reviewer stdout or a missing request is unknown, never a successful verification.
- Before repairing a dormant exporter, check its output against sharing boundaries: task titles, branches, paths, failure text and profile instructions can leak restricted project structure even when fact memory is correctly partitioned. Redacting credentials alone does not enforce institutional separation.
- Check remote refs before saying N commits are unpublished: cached origin refs can be stale. `git ls-remote` is read-only; if the advertised object is absent locally, ancestry/ahead counts remain unknown until a separately authorized fetch or isolated clone. Never push on that uncertainty.
- A check regex that recognizes pytest/git status is a reminder, not acceptance evidence. Test failure, wrong repo/SHA and empty test suites must not discharge a delivery gate. Reproduce with explicit synthetic fixtures; never call fixture outputs live production results.
- Treat approval waits as dormant. Retry only recoverable operational states, with a limit and acknowledgement after success. Notification deduplication is separate from retry scheduling.
- Preserve institutional separation. Inspect only reachable devices; do not infer RR deployment from FA snapshots. Never synchronize live SQLite files or secrets by git.
- Report implemented changes, provisioned work and suggestions separately. A backlog plus a report is not an operational automation. Include failed probes and unauthorized dispatch incidents rather than silently turning them into claimed success.
